RULES: No code comments. Lean, DRY, no speculative abstractions, no features outside the guide (excluded: Messenger/IG DM, VoIP, AI bots, ad management/ROAS, website builders, CSV import). No tests this phase. Valid migrations, runnable app, no broken imports. Work autonomously. End each task with a 10-line summary and anything unfinished.
STACK: Django + DRF, PostgreSQL, Celery + Redis, Docker Compose, drf-spectacular. API under /api/v1/.
TENANCY: every tenant-owned model inherits TenantOwnedModel (UUID pk, tenant FK non-null, timestamps). TenantScopedManager is fail-closed: raises if no tenant context is active. Celery tasks take tenant_id and activate context. Webhooks resolve tenant from provider identifiers before touching data. Serializers reject cross-tenant FK references. All unique constraints and indexes are tenant-prefixed.
PROVIDERS: per-tenant ChannelConnection with encrypted credentials. Provider code only in integrations/providers behind abstract interfaces returning normalized DTOs. Twilio tenant resolved by To/sender number then signature verified with that connection's token; SendGrid by per-tenant webhook path token plus signature; Meta by page_id with one platform Meta app from env.
EVENTS: core.events.publish(name, tenant_id, contact_id, payload) fires on transaction.on_commit and fans out to Celery subscribers. Events: lead_created, form_submitted, tag_added, tag_removed, lead_status_changed, lead_inactive, appointment_booked, appointment_cancelled, email_received, sms_received, whatsapp_received, message_sent, message_status_changed, conversion, external_event, assignment_changed. Subscribers: automation, inbox, notifications, outbound webhooks.
MESSAGING: MessagingService is the single path for all sends: consent/opt-out check, WhatsApp 24h window rule (template required outside window), placeholder rendering, SMS segment calc, persist Message, enqueue send, record usage.
AUTOMATION: durable graph (steps with branches), enrollment cursor, executor claims due enrollments with select_for_update(skip_locked), enrollment row locked on reply, workflows have is_promotional and exit-event rules.
APPOINTMENT: first-class model (contact, starts_at, status, external_ref).
CONVERSATION: one per contact, multi-channel, reopens on inbound.
SCALE: webhooks verify, store raw, ack, enqueue. Separate Celery queues: webhooks, messaging, automation, default. No provider calls in request cycle. Keyset pagination for messages/activity. Redis cache for dashboard. Design for 10k scale; never claim it without load testing.
AUTH: JWT with Membership roles (owner/admin/marketer); API keys + HMAC for external clients; marketer contact visibility is a tenant setting.
